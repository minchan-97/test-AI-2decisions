# 토론 XAI — 두 AI의 '결심 순간'을 층별로 열기

## 핵심 아이디어

LLM 에게 "왜 그렇게 생각해?"라고 물으면 **그럴듯한 설명을 지어낸다**
(post-hoc rationalization). 그 설명이 실제 계산과 같다는 보장이 없다.

→ 대신 **결론 토큰 직전의 내부**를 logit lens 로 연다.
   이건 실제 순전파의 중간 상태라 **지어낼 수 없다.**

## 설계상 타협 (정직하게)

| | 논증 품질 | 내부 관찰 |
|---|---|---|
| API 모델(GPT-4 등) | 좋음 | **불가능** (내부 접근 없음) |
| 작은 로컬 모델 | 유치함 | **가능** |

→ 관찰 가능성을 택했다. 논증은 유치하지만 내부는 진짜다.

## 핵심 기법: 결론을 한 토큰으로 고정

자유 생성하면 토큰 수백 개 = 순전파 수백 번 → 볼 수가 없다.
프롬프트를 `Answer:` 로 끝내 **" yes" / " no" 한 토큰**에서 승부를 보게 하고,
그 한 지점만 층별로 연다.

## 배포 (Streamlit Cloud)
1. GitHub 저장소에 `streamlit_app.py`, `requirements.txt` 업로드
2. share.streamlit.io → New app → Main file: `streamlit_app.py`
3. Deploy (첫 배포 5~10분)

`requirements.txt` 첫 줄의 `--extra-index-url` 이 CPU 전용 torch 를 받게 한다.
없으면 CUDA 포함 몇 GB 를 받아 실패.

## 로컬 실행
```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

## 보는 법

1. **결론 + 굳은 층** — 각 AI가 어느 층에서 답을 정했나
   - 같은 답이어도 굳은 시점이 다르면 = **확신의 깊이가 다름**
   - 차이가 미미하면 `[접전]` 으로 표시 (거짓 확신 방지)
2. **층별 확률 궤적** — yes/no 두 선이 어떻게 갈라지나
3. **층별 최상위 예측** — 결론 말고 뭘 생각하고 있었나

## 정직한 한계

- **분기가 아니라 흐름이다.** 어느 층에서도 `if A then yes` 같은 이산 결정은
  없다. 두 선택지가 계속 확률을 나눠 갖다가 한쪽이 앞설 뿐.
- **마지막 층 붕괴**: raw logit lens 의 알려진 한계. 최종 LayerNorm 이 이미
  적용된 상태에 또 적용해서 생긴다. 체크박스를 꺼서 비교해보라.
- **작은 모델의 한계**: distilgpt2/gpt2 는 이런 판단을 잘 못한다.
  접전이 자주 나오면 그것 자체가 관찰 결과다.
